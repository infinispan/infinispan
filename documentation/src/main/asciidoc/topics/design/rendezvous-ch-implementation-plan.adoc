= Rendezvous Consistent Hash Factory — Implementation Plan & Current State
:toc:

== Status

*All tests passing. Implementation complete.*

The implementation compiles and all tests pass with the current class hierarchy.

== Goal

Implement a family of rendezvous-based consistent hash factories for Infinispan's distributed cache
segment assignment, combining cross-cache determinism (like `SyncConsistentHashFactory`) with
near-minimal segment movement (like `DefaultConsistentHashFactory`), and history-hinted rebalancing
to further reduce unnecessary data movement across topology changes.

== Class Hierarchy

[source]
----
AbstractConsistentHashFactory
└── PureRendezvousConsistentHashFactory          (pure rendezvous, no caps/corrections)
    ├── RendezvousConsistentHashFactory            (Phase 1: rendezvous → Phase 2: SegmentOwnershipBalancer)
    └── HistoryHintedRendezvousConsistentHashFactory  (inherits build(); overrides rebalance() with history hints)
        └── TopologyAwareRendezvousConsistentHashFactory  (overrides build() with topology filter; inherits history rebalance)

SegmentOwnershipBalancer                         (standalone utility — the load-balancing post-processor)
TopologyFilter                                   (functional interface for per-position topology constraints)
----

All shared rendezvous infrastructure (`computeRankings`, `updateMembers`, `rebalance`, etc.) lives
in `PureRendezvousConsistentHashFactory`. Subclasses override `build()` and/or `rebalance()`.

The load-balancing logic (`redistributeTotal`, `redistributeSingleOwner`, `redistributePrimary`,
counting helpers) lives exclusively in `SegmentOwnershipBalancer`. Both `RendezvousConsistentHashFactory`
and `TopologyAwareRendezvousConsistentHashFactory` compose with it — they provide different initial
segment mappings (Phase 1) and then delegate to `SegmentOwnershipBalancer` for the balancing passes.

== Key Decisions

* `PureRendezvousConsistentHashFactory`: assigns segment owners by pure rendezvous rank (top-N
  from the score-sorted list), with no load cap, no balance correction, and no primary-swap pass.
  This is the **evaluation** factory — use it to observe raw rendezvous distribution quality.
* `RendezvousConsistentHashFactory`: extends the pure base; `build()` does Phase 1 (pure rendezvous
  initial assignment) then delegates Phase 2 to `SegmentOwnershipBalancer.apply()`.
* `HistoryHintedRendezvousConsistentHashFactory`: extends `RendezvousConsistentHashFactory`;
  inherits `build()` unchanged. Overrides `rebalance()` with a three-phase algorithm that:
  - Phase 1: pure rendezvous initial assignment (same as `RendezvousConsistentHashFactory.build()`)
  - Phase 2: history-hinted redistribution — prefer prior owners when draining over-loaded nodes
  - Phase 3: `SegmentOwnershipBalancer.apply()` for remaining excess and primary redistribution
  - Stable-state shortcut: when all segments have the right number of owners and all members have
    segments, skip Phases 1–2 and run only primary redistribution over the existing owner sets.
  This is the *default factory* for `DIST_SYNC` caches without topology information.
* `TopologyAwareRendezvousConsistentHashFactory`: extends `HistoryHintedRendezvousConsistentHashFactory`;
  overrides only `build()` with the topology-aware greedy algorithm (topology filter + caps +
  `balanceCorrection` + `redistributePrimary`). Inherits the history-hinted `rebalance()` from
  `HistoryHintedRendezvousConsistentHashFactory` — topology-aware caches also benefit from
  minimal segment movement across topology changes.
  This is the *default factory* for `DIST_SYNC` caches with topology information.
* `SegmentOwnershipBalancer`: package-private utility class — not a factory itself; not serialized;
  purely algorithmic. Can be composed with any initial segment mapping.
* `updateMembers`: coverage-only in `PureRendezvousConsistentHashFactory`, no greedy correction
  (deferred to `rebalance()`).
* `SIXTEEN_THREE` = `NodeVersion` constant for 16.3.0 (the minimum version for all rendezvous factories).
* ProtoTypeIds:
  - `RENDEZVOUS_CONSISTENT_HASH_FACTORY = CORE_LOWER_BOUND + 342`
  - `TOPOLOGY_AWARE_RENDEZVOUS_CONSISTENT_HASH_FACTORY = CORE_LOWER_BOUND + 343`
  - `PURE_RENDEZVOUS_CONSISTENT_HASH_FACTORY = CORE_LOWER_BOUND + 344`
  - `HISTORY_HINTED_RENDEZVOUS_CONSISTENT_HASH_FACTORY = CORE_LOWER_BOUND + 346`
* Version guard in `ClusterCacheStatus.effectiveConsistentHashFactory()` checks
  `instanceof PureRendezvousConsistentHashFactory` (catches all variants). Fallback selection
  checks `instanceof TopologyAwareRendezvousConsistentHashFactory`.

== Algorithm Description

=== `PureRendezvousConsistentHashFactory.build()`

[source,java]
----
// For each segment:
//   Walk the rendezvous ranking (score = hash(seg, msb, lsb) / cf, ascending)
//   Assign the first actualNumOwners eligible (non-zero-cap) nodes as owners.
// No cap enforcement, no balance correction, no primary-swap.
----

=== `RendezvousConsistentHashFactory.build()` (overrides pure)

[source,java]
----
// Phase 1: pure rendezvous initial assignment — top-N nodes per segment by score.
// Phase 2: SegmentOwnershipBalancer.apply()
//   2a: redistributeTotal — drain over-ceil nodes; candidates chosen by rendezvous rank.
//   2b: redistributePrimary — free position swaps to reach floor/ceil primary balance.
----

=== `HistoryHintedRendezvousConsistentHashFactory.rebalance()` (overrides base)

[source,java]
----
// Stable-state shortcut: if all segments have exactly actualNumOwners owners AND
// all non-zero-capacity members own ≥1 segment, skip Phases 1+2 and run only
// redistributePrimary over the existing owner sets. Return baseCH if nothing changed.

// Otherwise:
// Phase 1: pure rendezvous initial assignment (same as RendezvousConsistentHashFactory.build())
// Phase 2: history-hinted redistribution
//   For each overloaded node (owned > ceil(ideal)):
//     For each backup segment:
//       Check if any prior owner (from baseCH) is currently under-loaded.
//       If yes, prefer that prior owner — data already warm, no net movement cost.
// Phase 3: SegmentOwnershipBalancer.apply() — handles remaining excess + primary redistribution.
----

=== `TopologyAwareRendezvousConsistentHashFactory.build()` (overrides base)

[source,java]
----
// Phase 1: topology-aware greedy assignment (assignOwners with TopologyFilter + caps)
// Phase 2a: balanceCorrection (give ≥1 segment to any zero-owned eligible node)
// Phase 2b: SegmentOwnershipBalancer.redistributePrimary (iterative floor/ceil primary balance)
----

`rebalance()` is **inherited** from `HistoryHintedRendezvousConsistentHashFactory` — topology-aware
caches also get history-hinted rebalancing. Primary swaps within an existing owner set never change
which nodes own a segment, so topology diversity is always preserved across rebalances.

=== `SegmentOwnershipBalancer` — the composable load-balancing post-processor

The class is **not a factory**. It is a package-private utility that takes an already-built
`segmentOwners[][]` (from any source) and corrects load distribution in two passes:

==== `redistributeTotal` (and `redistributeSingleOwner` for numOwners=1)

Iterates until no node exceeds `ceil(ideal)` total ownership:

1. Find the most over-loaded node `W` (highest `owned - ceil(ideal)`).
2. *Pass 1 — backup-only swap*: scan segments where `W` is a backup (position ≥ 1). For each,
   find the highest-ranked candidate that is (a) not already an owner, (b) below `ceil(ideal)`.
   Choose the `(segment, candidate)` pair by: lowest candidate rank → highest `W` rank → most
   under-loaded candidate.
3. *Pass 2 — primary-vacating fallback* (if no backup swap possible): scan segments where `W`
   is primary. Promote the best-ranked existing backup to primary (free reorder), give the vacated
   backup slot to the best under-loaded candidate.
4. Repeat until no node exceeds `ceil(ideal)` or no move is possible.

Nodes that remain below `floor(ideal)` are intentionally left as-is.

==== `redistributePrimary`

Iterates until no node exceeds `ceil(primaryIdeal)` primary ownership:

1. Find the most over-primary node `W`.
2. Scan segments where `W` is primary; find backup `B` with `primaryOwned(B) < floor(primaryIdeal(W))`.
   Prefer lowest rendezvous rank for `B`.
3. Swap `W` and `B` within the segment's owner list (zero data movement).

==== Entry points

* `apply(segmentOwners, rankings, members, capacityFactors, numSegments, actualNumOwners)` —
  runs both passes (total + primary). Use this for the standard non-topology-aware case.
* `redistributePrimary(...)` — runs only the primary pass. Use when Phase 1 already handles
  total-ownership balance (e.g. topology-aware greedy + `balanceCorrection`).
* `countOwned(...)` / `countPrimaryOwned(...)` — counting helpers, also available to callers
  that need ownership counts before calling the redistribution methods.

=== `computeIdeals()` — capped ideal

[source,java]
----
// Sort members by descending capacity factor.
// Process in that order:
//   rawIdeal = remainingCopies * cf / remainingCap
//   if rawIdeal > numSegments: cap at numSegments, update remaining
//   else: use rawIdeal
----

== Rolling Upgrade

The version guard in `ClusterCacheStatus.effectiveConsistentHashFactory()` ensures that all
rendezvous factories degrade gracefully during rolling upgrades:

* While any cluster member is below `NodeVersion.SIXTEEN_THREE` (16.3.0):
  - `TopologyAwareRendezvousConsistentHashFactory` → falls back to `TopologyAwareSyncConsistentHashFactory`
  - All other rendezvous variants → fall back to `SyncConsistentHashFactory`
* Once all members reach 16.3.0, the configured factory is activated and a full rebalance
  redistributes segment ownership. The transition is logged exactly once.

== Current State of the Tests

=== `RendezvousConsistentHashFactoryTest`

Tests `PureRendezvousConsistentHashFactory`. Distribution enforcement is **intentionally disabled**:
`checkDistribution()` only verifies that each segment has the correct number of distinct owners
(structural check). Movement tolerance is also relaxed (`allowedExtraMoves` = full segment count)
since the pure factory makes no bounded-load guarantees.

=== `TopologyAwareRendezvousConsistentHashFactoryTest`

Tests `TopologyAwareRendezvousConsistentHashFactory`. Inherits the permissive distribution
tolerances from `RendezvousConsistentHashFactoryTest`. Topology diversity tests (distinct
sites/racks) are enforced as-usual.

=== `HistoryHintedRendezvousConsistentHashFactoryTest`

Tests `HistoryHintedRendezvousConsistentHashFactory` directly: basic distribution, idempotent
rebalance, stable-state shortcut, and the two-node/two-segment primary ownership assertion.

=== Other tests

* `RendezvousConsistentHashDeterminismTest` — verifies determinism of `PureRendezvousConsistentHashFactory`.
* `RendezvousCapacityFactorTest` — tests proportional capacity factor allocation with 256 segments.
* `RendezvousSegmentMovementTest` — tests movement bounds (relaxed tolerance applies).
* `ConsistentHashFactoryComparisonTest` — compares `RendezvousConsistentHashFactory` movement vs Sync.
* `RendezvousRollingUpgradeCompatibilityTest` — verifies ProtoTypeIds and version guard.

== Important API Notes

* `Address.getUUID()` does NOT exist — use `getMostSignificantBits()` / `getLeastSignificantBits()`
* `MurmurHash3.hash(int, long, long)` does NOT exist — use `MurmurHash3.hash(new long[]{s, msb, lsb})`
* `DefaultConsistentHash.create()` preserves member list order as-passed — `equals()` fails if members are in different order even with same assignments
* `computeCaps` and `computeIdeals` are package-private (not `private`) so subclasses can call them
* `SegmentOwnershipBalancer` methods are all package-private — accessible to all classes in `org.infinispan.distribution.ch.impl`
* Version guard (`effectiveConsistentHashFactory`) checks `instanceof PureRendezvousConsistentHashFactory` — catches all 4 variants
* Fallback to topology-aware sync checks `instanceof TopologyAwareRendezvousConsistentHashFactory`
