= Relay nodes

Relay nodes are the nodes in {brandname} clusters that are responsible for sending and receiving requests from backup locations.
If a node is not a relay node, it must forward backup requests to a local relay node.

For optimal performance, configure all nodes as relay nodes. 
This increases the speed of backup requests because each node in the cluster can send backup requests directly to remote clusters without forwarding them to local relay nodes.

To configure all nodes as relay nodes, set the `max_site_masters` attribute of the JGroups `RELAY2` protocol to a value greater than the number of nodes in the cluster.

For an example of a JGroups `RELAY2` configuration, see xref:configuring-cluster-transport-cross-site_configuring-cross-site-replication[Configuring cluster transport for cross-site replication].

[NOTE]
====
If you use two-phase commit with cross-site replication, configure exactly one relay node per cluster.
For more information, see xref:cross-site-backup-strategies_cross-site-replication[Backup strategies].
====

[NOTE]
====
Diagrams in this document illustrate {brandname} clusters with one relay node because this is the default for the JGroups RELAY2 protocol.
Likewise, a single relay node is easier to illustrate because each relay node in a cluster communicates with each relay node in the remote cluster.
====

[NOTE]
====
JGroups configuration refers to relay nodes as "site master" nodes.
{brandname} uses relay node instead because it is more descriptive and presents a more intuitive choice.
====
